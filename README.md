# elina-assistant

Локальный голосовой помощник: **llama.cpp** крутит LLM на вашем железе,
Python-обвязка запускает сервер, общается с ним по HTTP и слушает
активационное слово **«Элина»** — офлайн, без API-ключей и подписок.

```
микрофон → Vosk («Элина» + распознавание фразы) → llama-server → ответ
```

Рассчитан и на обычный ПК, и на Raspberry Pi (сборка `build.sh` умеет
`x86_64`, `arm64`, `armv7`).

---

## Возможности

* запуск/остановка `llama-server` из Python, выбор `.gguf` модели;
* чат с моделью через OpenAI-совместимый `/v1/chat/completions`;
* активация голосом по слову «Элина» — офлайн-детектор на Vosk, ~45 МБ,
  работает на CPU, срабатывает за 0,2–0,3 с;
* распознавание самой команды после слова (тем же движком, без второго пакета);
* инструменты для ИИ: погода, время, запуск программ, ссылки, свои функции
  в `tools/` в пять строк — и любые **MCP-серверы** из конфига;
* голосовые ответы: Piper (нейроголос) или espeak-ng, движок выбирается
  в меню и сохраняется в конфиге;
* авто-запуск `llama-server` при старте программы;
* консольное меню, чтобы всё это дёргать.

## Установка

Всё делает один скрипт — `build.sh`:

1. проверяет зависимости (Python 3.9+, `git`, `cmake`, `c++`, `unzip`, `curl`);
2. создаёт `.venv` и ставит в него `vosk` + `sounddevice`;
3. качает модель распознавания `vosk-model-small-ru-0.22` (~45 МБ) в `models/`;
4. собирает `llama.cpp` под вашу архитектуру и пишет `llama/arch.json`;
5. качает LLM `LFM3-1.7B-Q4_K_M.gguf` (~1 ГБ) в `llama/gguf/`;
6. по желанию ставит озвучку: `PIPER=1 bash build.sh` добавляет `piper-tts`
   и русский голос (~65 МБ) в `models/piper/`.

```bash
git clone <repo> elina-assistant
cd elina-assistant

bash build.sh          # первый раз долго: сборка llama.cpp + ~1 ГБ модели
PIPER=1 bash build.sh  # то же плюс озвучка Piper
source .venv/bin/activate
```

Скрипт идемпотентный: повторный запуск не качает модели заново и не
переставляет пакеты, если `requirements.txt` не менялся. Обрыв соединения при
скачивании LLM не страшен — файл докачивается с места остановки.

Свою `.gguf` можно положить в `llama/gguf/` и выбрать в меню пунктом `1`.
Другая LLM скачивается так:

```bash
LLM_FILE=LFM3-1.7B-Q8_0.gguf bash build.sh
```

Нужны: интернет на время установки и микрофон для голосового режима. В
рантайме ничего не скачивается — после `build.sh` помощник работает офлайн.
`llama/arch.json` создаёт тот же скрипт: без него `Llama` не стартует.

## Запуск

```bash
source .venv/bin/activate
python main.py
```

Меню:

| Клавиша | Действие |
|---|---|
| `1 модель` | выбрать `.gguf` из `llama/gguf/` |
| `2 запуск` | запустить `llama-server` (порт 8080) |
| `3 стоп` | остановить сервер |
| `4 чат` | текстовый вопрос-ответ |
| `5 лог` | последние строки лога сервера |
| `6 голос` | голосовой режим: «Элина» → вопрос → ответ вслух |
| `7 озвучка` | движок: авто / piper / espeak-ng / выкл |
| `8 авто-старт LLM` | поднимать `llama-server` при старте программы |
| `9 настройка` | мастер: модель, голос, авто-старт |
| `0 выход` | выход |

Типичный сценарий: `1` → `2` → `4` (или `6`). И `4`, и `6` умеют
пользоваться инструментами: «какая погода в Москве», «запусти браузер»,
«который час».

`8 авто-старт LLM` сохраняет `autostart_llm: true`: при следующем запуске
`python main.py` сервер поднимется сам, без пункта `2`.

`2 запуск` теперь действительно ждёт загрузки модели (до 2 минут на Pi) и
сообщает об ошибке, если сервер не поднялся, — а не делает вид, что всё
хорошо. На выходе (`0`, Ctrl+C) сервер останавливается сам.

## Первичная настройка

При первом запуске `python main.py` сам предложит три шага: выбрать модель из
`llama/gguf/`, движок озвучки и авто-запуск LLM. Ответы сохраняются в
`config.json`, инструменты — в `tools/tools.json`.

Повторить в любой момент:

```bash
python main.py --setup      # только мастер, без меню
```

или пункт `9 настройка` в меню. Мастер не обязателен: `config.json` и
`tools/tools.json` можно править руками.

Если остался старый общий `config.json`, где лежали и настройки, и `tools`
с `mcp`, при первом запуске они переедут в `tools/tools.json` автоматически.

## Голосовой режим («Элина»)

`6 голос` — полноценный диалог: ждёт слово, записывает фразу до паузы,
отвечает в чат и **проговаривает ответ вслух**. Цикл повторяется, пока не
скажете «пока»/«выход» или не нажмёте Ctrl+C.

Работают оба варианта:

* **«Элина, какая сегодня погода?»** — одной фразой;
* **«Элина»** → пауза → **«какая сегодня погода?»**.

Озвучку можно проверить отдельно:

```bash
python -m core.voice --list           # какие движки доступны
python -m core.voice --say "привет"   # озвучить фразу
```

Проверить только детектор, без меню и без llama:

```bash
python -m core.wakeword              # слушать и печатать ЭЛИНА
python -m core.wakeword --command    # печатать распознанную фразу
python -m core.wakeword --wav test.wav
python -m core.wakeword --list-devices
```

Настройки — параметры класса `WakeWord`:

```python
WakeWord(
    word="элина",        # кодовое слово
    threshold=0.82,      # строже/мягче срабатывание (0…1)
    cooldown=2.0,        # пауза между срабатываниями, сек
    device=None,         # микрофон: номер или часть названия
    verbose=False,       # показывать, что слышно
)
```

Модель `vosk-model-small-ru-0.22` (~45 МБ) ставит `build.sh` в `models/`;
сам Python ничего не качает. Если папки нет, модуль честно скажет запустить
`build.sh`. `models/` добавлен в `.gitignore`.

Движок — Vosk (Apache-2.0), модель — `vosk-model-small-ru-0.22`. Распознавание
идёт на CPU: на обычном ноутбуке ~13× быстрее реального времени, то есть
детектор занимает около 7 % одного ядра.

## Озвучка: Piper и espeak-ng

Движок выбирается в меню пунктом `7` и сохраняется в `config.json`:

```json
"voice": {"engine": "auto", "model": "models/piper/ru_RU-irina-medium.onnx"}
```

* `auto` — Piper, если установлен, иначе espeak-ng;
* `piper` — нейроголос, офлайн, естественное звучание (~65 МБ модель);
* `espeak-ng` — системный синтезатор, робот, зато лёгкий;
* `none` — без озвучки, только текст.

Piper ставится без root:

```bash
PIPER=1 bash build.sh        # piper-tts + голос в models/piper/
```

или вручную в активированный venv:

```bash
pip install piper-tts
# модель: https://huggingface.co/rhasspy/piper-voices/tree/main/ru/ru_RU/irina/medium
```

espeak-ng ставится системно:

```bash
sudo pacman -S espeak-ng      # CachyOS/Arch
sudo apt install espeak-ng    # Debian/Ubuntu/Raspberry Pi OS
```

Звук выводится через `sounddevice`, при проблемах — через `paplay`,
`pw-play` или `aplay`. Если движка нет, голосовой режим продолжает работать
текстом и один раз предупреждает в консоли.

## Инструменты и MCP

ИИ не только отвечает, но и вызывает инструменты. Схема сознательно простая —
работает с любой моделью, а нативный tool-calling у 1.7B ломается чаще, чем
помогает:

1. в системный промпт попадает список инструментов;
2. модель отвечает JSON `{"tool": "имя", "args": {...}}`;
3. `core/agent.py` выполняет вызов и отдаёт результат обратно модели;
4. модель формулирует ответ (до 3 шагов, потом просит ответить текстом).

Встроенные инструменты (работают сразу):

| Инструмент | Что делает |
|---|---|
| `get_weather(city)` | погода через wttr.in — бесплатно, без ключа |
| `get_time()` | дата, время, день недели |
| `open_app(name)` | запуск программы из белого списка |
| `open_url(url)` | открыть сайт в браузере |

Проверить без модели и без llama:

```bash
python -m core.tools --list
python -m core.tools --call get_weather '{"city": "Москва"}'
```

### Добавить свой инструмент

**Способ 1 — файл в `tools/`.** Создайте `tools/my.py` (образец уже лежит —
`tools/example.py`):

```python
from core.tools import tool

@tool("battery", "заряд батареи")
def battery() -> str:
    return "87%"

@tool("set_volume", "установить громкость 0-100")
def set_volume(level: int) -> str:
    subprocess.run(["amixer", "-q", "sset", "Master", f"{level}%"])
    return f"громкость {level}%"
```

Всё, что нужно: декоратор и аннотации типов. Модель присылает аргументы
строками — `int`, `float` и `bool` приведутся автоматически. Описание берётся
из второго аргумента или из первой строки докстринга. Перезапустили
`main.py` — инструмент у ИИ.

**Способ 2 — строка в `tools/tools.json`**, если аргументы не нужны и хватает
shell-команды:

```json
"tools": {
  "commands": {
    "uptime": {"description": "сколько работает компьютер", "run": "uptime -p"}
  }
}
```

Проверка, что подхватилось (в скобках — источник):

```bash
python -m core.tools --list
python -m core.tools --call set_volume '{"level": 40}'
```

Сломанный файл не роняет помощника: предупреждение в консоль, остальные
инструменты работают.

### Программы

`build.sh` создаёт `tools/tools.json` из `tools.example.json`. Впишите свои:

```json
{
  "tools": {
    "apps": {
      "браузер": "firefox",
      "блокнот": "gedit",
      "калькулятор": "gnome-calculator"
    }
  }
}
```

Модель **не может** выполнить произвольную shell-команду — только эти записи.
Это сделано специально: иначе «запусти прогу» превращается в «выполни что
угодно».

### MCP-серверы

Любой MCP-сервер с stdio-транспортом подключается в секции `mcp`:

```json
{
  "mcp": {
    "files": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/me/docs"],
      "enabled": true
    }
  }
}
```

Его инструменты появятся у ИИ как `files.read_file`, `files.search_files` и
т.д. — с описаниями из `inputSchema`. `enabled: false` выключает сервер.

Нужен node/npx (или любой исполняемый MCP-сервер). Проверка:

```bash
python -m core.tools --list      # покажет и встроенные, и MCP-инструменты
```

### Ограничения

* чем меньше инструментов, тем лучше для 1.7B: 5–10 понятных лучше, чем 40
  случайных (поэтому MCP-серверы подключайте по одному и проверяйте);
* приветствия, «как дела», «спасибо» и прощания идут мимо инструментов —
  на них модель отвечает обычным текстом;
* 1.7B иногда криво пишет JSON — агент сам чинит лишние кавычки и запятые,
  а если не вышло, просит повторить; сырой JSON в чат не попадает;
* MCP-серверы стартуют при первом вопросе, `npx` может подумать пару секунд;
* на Pi берите лёгкие серверы (filesystem, time) — тяжёлые будут тормозить.

## Raspberry Pi 5

Нужна **64-битная** система (Raspberry Pi OS Bookworm 64-bit): для `aarch64`
есть готовые wheel-пакеты `vosk` и `sounddevice`, ничего собирать не придётся.

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip libportaudio2 portaudio19-dev \
                    build-essential cmake git unzip curl

bash build.sh            # venv + зависимости + Vosk-модель + llama.cpp под arm64
source .venv/bin/activate
```

Понадобится ~1,5 ГБ свободного места: LLM ~1 ГБ + Vosk 45 МБ + сборка.
Остальное — как на ПК: `python main.py`. Для Pi 5 `LFM3-1.7B Q4_K_M` — как раз
подходящий размер: ~1 ГБ в памяти, 4 потока.

Проверка скорости детектора именно на вашей плате (данные лучше обещаний):

```bash
python -m core.wakeword --bench test.wav
# аудио 18.62 c, обработка 4.10 c (x4.5 реального времени)
```

Ориентиры:

| | Ноутбук (x86_64) | Raspberry Pi 5 |
|---|---|---|
| Детектор «Элина» | ~13× реального времени | ~4–6× (≈15–25 % одного ядра) |
| Задержка срабатывания | 0,2–0,3 с | 0,2–0,4 с |
| Память под детектор | ~150 МБ | ~150 МБ |

Советы для Pi:

* модель для llama.cpp — до 3B параметров, квантование `Q4_K_M`;
* `Llama.start(threads=4)` — все 4 ядра у Pi 5;
* озвучка: Piper на Pi 5 работает, но тянет onnxruntime и ~65 МБ голос;
  espeak-ng заметно легче — для слабых плат лучше он;
* если детектор и модель конкурируют за CPU, запускайте помощника с
  `nice -n 5 python main.py`, а сервер оставляйте в обычном приоритете;
* микрофон подключайте USB — встроенный аналоговый вход Pi шумит.

## Частые проблемы

**`ModuleNotFoundError: vosk` / `sounddevice`** — активируйте venv:
`source .venv/bin/activate`; если пакетов нет — `bash build.sh`.

**`Модель распознавания речи не найдена`** — `build.sh` не запускался:
`bash build.sh` скачает её в `models/`.

**`llama-server не запустился`.** Смотрите `5 лог`: первые строки обычно
объясняют причину. Скрипт сам пробует три набора флагов под разные версии
llama.cpp; если не подошёл ни один — обновите сборку `bash build.sh`.

**ИИ отвечает пустой строкой.** LFM3 по умолчанию «думает»: при включённом
thinking бюджет уходит на `reasoning_content`, а `content` приходит пустым.
Сейчас thinking выключен двумя способами — `--reasoning off` у сервера и
`chat_template_kwargs.enable_thinking=false` в запросе. Если включаете обратно,
поднимите `Api.max_tokens` (минимум 1024).

**ИИ не пользуется инструментами.** Проверьте `python -m core.tools --list`:
если список пуст — нет `tools/tools.json`
(`cp tools.example.json tools/tools.json`).
Слабые модели иногда отвечают текстом вместо JSON — переформулируйте вопрос.

**MCP-сервер не запускается.** Нет команды (`npx`, `python`, путь) или сервер
упал: посмотрите вывод `python -m core.tools --list`, там будет причина.

**`Не удалось скачать модель LLM`** — проверьте место на диске (~1 ГБ) и
интернет; повторный `bash build.sh` докачает файл с места обрыва. Вручную:
`https://huggingface.co/LiquidAI/LFM3-1.7B-GGUF` → `LFM3-1.7B-Q4_K_M.gguf`
в `llama/gguf/`.

**`llama не собран`** — не собран llama.cpp: `bash build.sh`.

**`Ошибка подключения к ИИ`** — не запущен сервер: пункт `2 запуск`, проверить
`5 лог`; порт задаётся в `core/config.py`.

**Не слышит слово.** Проверьте микрофон: `python -m core.wakeword --list-devices`,
затем `--device "USB"` (номера устройств зависят от сессии). Порог можно
опустить: `--threshold 0.78`.

**Ложные срабатывания.** Поднимите порог до `0.88`, уменьшите `cooldown`.

**`Ошибка аудио` в Linux** — нет PortAudio: `sudo apt install libportaudio2`.

**`голос: нет TTS`** — не установлен движок: `PIPER=1 bash build.sh`
или `sudo pacman -S espeak-ng` (Debian/Ubuntu — `apt install espeak-ng`).

**`голос: не удалось воспроизвести звук`** — проверьте громкость и
устройство вывода; вручную: `paplay файл.wav` или `aplay файл.wav`.

**Микрофон не поддерживает 16 кГц** — модуль сам пересчитывает частоту
(чистый Python, без numpy).

**Старый `templates/pyopen-wakeword.py`.** Это эксперимент с openWakeWord:
там английские встроенные модели, слова «Элина» среди них нет, и он требует
`pyaudio`. Актуальный детектор — `core/wakeword.py`.
